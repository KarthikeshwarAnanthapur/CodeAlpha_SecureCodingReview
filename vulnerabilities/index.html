Security Analysis

Common Vulnerabilities

Five of the most commonly found security vulnerabilities in web applications, with explanations, severity ratings, and prevention tips.

SQL Injection
● Critical
🗄️

SQL Injection occurs when untrusted user input is inserted directly into a SQL query without sanitization. An attacker can manipulate the query to read, modify, or delete database data — or even take over the server.

// ⚠️ Vulnerable
"SELECT * FROM users WHERE name='" + userInput + "'"
FIX: Use parameterized queries or prepared statements. Never concatenate user input directly into SQL strings.
CVE-OWASP-A03 · OWASP Top 10 #3
Cross-Site Scripting (XSS)
● High
⚠️

XSS allows attackers to inject malicious scripts into web pages viewed by other users. This can be used to steal cookies, session tokens, redirect users, or perform actions on behalf of the victim without their knowledge.

// ⚠️ Vulnerable
element.innerHTML = userInput; // Never!
FIX: Use textContent instead of innerHTML. Encode output and implement a strict Content Security Policy (CSP).
CVE-OWASP-A03 · OWASP Top 10 #3
Weak Passwords
● High
🔓

Applications that allow weak, short, or common passwords make it trivial for attackers to gain unauthorized access via brute force or credential stuffing attacks. Storing passwords in plain text compounds the risk dramatically.

// ⚠️ Vulnerable
if (password.length >= 4) allowed(); // Too weak!
FIX: Enforce minimum 12+ character passwords with complexity rules. Hash passwords with bcrypt or Argon2. Enable MFA.
CVE-OWASP-A07 · OWASP Top 10 #7
Hardcoded Credentials
● Critical
🔑

Embedding passwords, API keys, or secrets directly in source code is one of the most dangerous mistakes a developer can make. If the code is ever exposed (e.g., through a public GitHub repo), attackers immediately gain access to critical systems.

// ⚠️ Vulnerable — Never do this!
const DB_PASS = "admin123";
const API_KEY = "sk-abc123secret";
FIX: Store credentials in environment variables or a secrets manager (e.g., AWS Secrets Manager, HashiCorp Vault). Never commit secrets to version control.
CVE-OWASP-A02 · OWASP Top 10 #2
Insecure Input Validation
● Medium
📝

Failing to validate and sanitize user-provided data allows attackers to submit unexpected input that can break application logic, trigger injection attacks, or cause crashes. Relying on client-side validation alone is never sufficient.

// ⚠️ No server-side validation
const age = req.body.age; // could be "abc" or -1
db.save({ age }); // stored without checks
FIX: Always validate and sanitize input on the server side. Use allowlists, type checking, and schema validation libraries like Joi or Zod.
